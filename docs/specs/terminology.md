# Domain Terminology & Specifications

This document establishes the Ubiquitous Language, domain terminology, and specifications for the Telecom Data Platform.

---

## 1. Glossary of Terms

| Term | Definition | Context / Scope |
| :--- | :--- | :--- |
| **Antenna** | A static physical cellular transmitter/receiver unit. Represents the net-infra static dimension. | Relational Database (PostgreSQL) |
| **Antenna Event** | A high-frequency, immutable telemetry log record generated by network activities (voice/data). | Document Database (MongoDB) |
| **Theoretical Capacity** | The theoretical maximum throughput or bandwidth configuration of an antenna. Measured in Megabits per second (Mbps). | Domain Invariant |
| **Traffic Load** | The aggregated data volume or call durations handled by an antenna within a given time frame. | Analytical / Query |
| **Saturated Antenna** | An antenna whose current aggregate Traffic Load exceeds 80% of its Theoretical Capacity. | Analytical / Query |
| **VOICE_CALL** | A type of Antenna Event representing a voice connection. Typically measured in seconds/milliseconds (`duration_ms`). | Telemetry Event |
| **DATA_SESSION** | A type of Antenna Event representing a data connection. Typically measured in bytes (`bytes_transferred`). | Telemetry Event |
| **Exactly-Once** | Processing constraint guaranteeing that duplicate incoming events (due to SQS retries) do not result in duplicate records. | Ingestion Layer |
| **Optimistic Locking** | Concurrency control strategy using versioning (`@Version`) to detect and handle simultaneous modification conflicts. | Persistence Layer |

## 2. Schema Specifications

### PostgreSQL `antennas` Table
Stores static infrastructural master data.

```sql
CREATE TABLE antennas (
    id VARCHAR(50) PRIMARY KEY,
    location VARCHAR(255) NOT NULL,
    type VARCHAR(10) NOT NULL, -- e.g., '3G', '4G', '5G'
    theoretical_capacity INT NOT NULL, -- in Mbps
    status VARCHAR(20) NOT NULL -- e.g., 'ACTIVE', 'INACTIVE', 'MAINTENANCE'
);
```

### MongoDB `antenna_events` Collection
Stores high-frequency, append-only raw events.

```json
{
  "_id": "ObjectId",
  "event_id": "String (Unique ID for Idempotency)",
  "antenna_id": "String (FK referencing antennas.id)",
  "event_type": "String (VOICE_CALL | DATA_SESSION)",
  "duration_ms": "Long",
  "bytes_transferred": "Long",
  "timestamp": "ISODate",
  "version": "Integer (Optimistic Locking version)"
}
```

## 3. Core Domain Rules & Invariants

1. **Immutable Facts:**
   * Once an `antenna_event` is written, it cannot be modified or deleted. 
   * Updates are only permitted during ingestion for concurrency control/retries if checking status, but generally the stream is append-only.

2. **Idempotency Rule:**
   * Two messages arriving with the exact same `event_id` must result in only one persistent record in the database.
   * If a message is retried, the consumer must detect the duplicate `event_id` and acknowledge the message without saving it again.

3. **Saturability Condition:**
   * Saturated antennas are computed as: `SUM(bytes_transferred) > (theoretical_capacity * 0.8)` or similar telemetry-aggregate conditions relative to the capacity limit.
